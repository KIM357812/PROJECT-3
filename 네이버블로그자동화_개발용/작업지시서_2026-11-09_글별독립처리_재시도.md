# 네이버 블로그 자동화 글별 독립 처리·실패 재시도 작업 지시서

## 목적

사용자가 선택한 1~3개 기사를 서로 독립된 작업으로 처리한다. 한 글의 생성·검증 실패가 다른 완성 글의 사용을 막지 않으며, 실패 글은 기사 재검색과 번호 재선택 없이 같은 실행 상태에서 다시 작성한다.

## 설계 원칙

1. 기사 검색·사용자 선택과 글 생성·네이버 변환을 분리한다.
2. 선택 기사마다 Candidate, Completed, Failed, 원문 경로와 네이버 패키지 경로를 상태 파일에 보존한다.
3. 성공 글은 즉시 독립 실행 패키지로 제공하고 실패 글은 후보·번호·제목·오류를 보존한다.
4. 완성 글이 한 건 이상이면 전체 실행을 실패 처리하지 않는다.
5. 완성 글이 0건이어도 실패 후보를 삭제하지 않고 재시도 가능한 결과로 반환한다.
6. 재시도는 가장 최근 실패 상태의 실패 글만 실행한다. 기사 검색, 16개 후보 생성과 번호 선택을 다시 실행하지 않는다.
7. 이미 완성된 글과 이미 만든 네이버 실행 패키지는 다시 만들거나 덮어쓰지 않는다.
8. 원문 콘텐츠 생성과 네이버 변환을 분리한다. 네이버에서 결정 가능한 표 data-label, 참고자료·관련 글 상자 서식 등은 코드로 자동 교정한 뒤 검증한다.
9. 사실·링크·제목·원문 날짜처럼 코드가 추정할 수 없는 오류만 해당 글 실패로 남긴다.

## 사용자 화면

- 최신 기사로 새 글 만들기: 최근 7일 기사 검색과 사용자 번호 선택으로 새 실행을 만든다.
- 실패한 글만 다시 작성: 보존된 최근 실패 글만 재시도한다.
- 완성 글 편집기 입력 계속: 이미 만든 실행 패키지를 선택해 편집기 입력을 재개한다.
- 완성 글과 실패 글을 같은 목록에 명확히 구분해 표시한다.
- 완성 글이 한 건이어도 자동으로 편집기에 넣지 않고 사용자가 선택한다.
- 실패 항목은 편집기 입력 버튼으로 실행할 수 없고 재시도 버튼을 안내한다.

## 결과 계약

- Completed: 선택 글이 모두 완성됨
- PartiallyCompleted: 완성 글과 실패 글이 함께 있음
- Failed: 완성 글은 없지만 실패 후보가 보존됨
- 결과에는 completedCount, failedCount, canRetryFailed, runStatePath, packages, failures를 포함한다.

## 필수 시험

1. 3개 중 2개 성공·1개 실패 시 성공 2개가 즉시 표시되는가
2. 실패 1개만 재시도하며 검색·선택을 반복하지 않는가
3. 재시도 후 기존 성공 패키지가 중복 생성되지 않는가
4. 선택 순서가 보존되는가
5. 결과가 0건이어도 실패 후보가 보존되는가
6. 네이버 자동 교정 가능한 서식 오류가 글 전체 실패를 만들지 않는가
7. Google 참조 원본 238개가 변경되지 않는가
8. 발행 설정을 열거나 공개·비공개 발행을 실행하지 않는가

## 완료 조건

전체 회귀 테스트, 부분 성공·실패 전용 테스트, GUI 자체·배치 테스트, Google 원본 무결성 검사를 모두 통과하고 작업 브랜치에 커밋·업로드한다.
