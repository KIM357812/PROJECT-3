반복되는 본문·서식 수정은 컴퓨터 사용으로 시험 글만 직접 보정하지 않는다. 자동화 도구에 생성·적용 기능과 회귀 검증을 구현하고 그 도구를 실행해 시험 글에 적용한 뒤 실제 PC·모바일 결과를 확인해야 완료로 처리한다.

도구 모음의 글자 크기·줄간격을 바꾼 뒤 포커스가 본문으로 돌아오지 않아 문단이 누락되거나 합쳐질 수 있는 실제 실패를 확인했다. 모든 동작 전에 본문 포커스를 확인하고, 동작 직후 독립 문단 수·정확한 문자열·합침 여부·간격 문단 높이를 기록하는 `편집기재구성실행검증.ps1`을 추가했다. 하나라도 다르면 저장을 허용하지 않는다.

2026-11-07 후속 화면 증거에서 구간 HTML의 CSS 여백이 올바르더라도 네이버 편집기가 소제목과 본문을 같은 구성요소로 평탄화하는 회귀가 확인되었다. 따라서 이전의 구간 HTML 일괄 붙여넣기 완료 판정은 무효로 하고, 글쓰기 프롬프트와 패키지 생성기를 원자 편집 계획으로 교체했다. 모든 소제목은 `위 32px 간격 → 독립 소제목 → 아래 21px 간격`, 모든 일반 문단은 한 블록·뒤 18px으로 생성하며 `PasteRenderedSegment`가 하나라도 있거나 소제목이 본문 블록에 섞이면 패키지 생성 자체를 실패시킨다. 사용자의 지시에 따라 이 후속 수정에서는 실제 네이버 글을 직접 수정하지 않았다.

## 2026-11-07 편집기 서식 근본 원인과 조치
