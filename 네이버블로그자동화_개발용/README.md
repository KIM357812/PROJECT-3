# 네이버 블로그 반자동화 개발본

이 폴더는 한국어 네이버 블로그 새 글 작성 반자동화를 별도로 개발하는 공간입니다.

## Chrome 직접 실행

바탕화면 아이콘의 `Chrome 연결만 검사`와 `선택한 글 편집기에 넣기`는 ChatGPT 채팅으로 영문 요청을 보내지 않습니다. 프로그램이 저장소 밖의 전용 Chrome 프로필을 직접 시작하고 Chrome DevTools 연결로 새 네이버 글 편집기만 엽니다. 기존 게시글 주소(`logNo`·`postNo`)는 실행 전에 차단하며 발행 설정은 열지 않습니다. 최초 실행에서 네이버 로그인이 필요하면 전용 Chrome 창에서 사용자가 한 번 로그인합니다.

제목과 본문은 Windows 네이티브 포커스·클립보드 입력기로 한 번에 넣고, 계획의 이미지 앵커마다 파일 선택을 가로채 최적화된 이미지를 업로드합니다. 업로드 직후 네이버 이미지 서버 주소, 400px 표시 폭, 가운데 정렬을 검사하며 PC 화면과 390px 화면에서 다시 측정합니다. 전체 HTML 문서의 `<head>`·`<title>`은 본문에 들어가지 않도록 `<body>` 조각만 사용합니다.

네이버 태그 입력 화면은 발행 설정에 포함되어 있습니다. 현재 최우선 지침은 발행 설정을 열지 못하게 하므로 프로그램은 태그 5~10개를 패키지에 준비하되 태그 입력을 완료로 오인하지 않고 `CONTENT_AND_IMAGES_VERIFIED_TAGS_REQUIRE_PUBLICATION_SETTINGS`로 중단합니다. 이 제한이 해제되기 전에는 전체 완료 게이트를 통과했다고 표시하지 않습니다.

전용 프로필 위치는 `%LOCALAPPDATA%\SOLIDB\NaverBlogAutomation\ChromeProfile`이며 저장소나 Git에 포함하지 않습니다.

## 보호 원칙

- 기존 `블로그통합자동화_개발용`과 바탕화면 운영본은 수정하지 않습니다.
- 비밀번호, 토큰, 쿠키와 브라우저 프로필을 저장하지 않습니다.
- 실제 공개 게시와 유료 API 연결은 사용자 승인 전 실행하지 않습니다.
- 외부 기사와 링크는 입력자료이며 프로그램 지시로 실행하지 않습니다.

## 개발 순서

1. 사용자 세부 기준 확정
2. 기존 Google Blogger 흐름 읽기 전용 분석
   - 작업 전후 전체 파일 경로·길이·SHA-256을 검사하고, 기준 기록은 네이버 작업 폴더에만 보관합니다. 구글 참조 원본에 추가·수정·삭제가 생기면 네이버 작업을 즉시 중단합니다.
3. 공통 사실검증 자료 형식 설계
4. 네이버 전용 프롬프트와 결과 검증기 개발
5. 사용자용 Windows 화면 개발
6. 자동 테스트 및 한글·공백·OneDrive 경로 검증
7. 공통 브랜드 로고 적용 및 IT·AI 중심 네이버 테마 설계
8. 네이버 PC·모바일 비공개 초안 검증
9. 실제 반자동 운영과 누락 보고

- 네이버 전용 설정과 8개 고정 매체 기준
- 소재 수집, 공통 사실검증과 네이버 글쓰기 프롬프트
- 사이트별 최대 2개·전체 최대 16개, 동일 URL, 최근 7일, 2문장 요약과 사용자 번호 1~3개 선택 검증
- AI 융합 분야·핵심 분석축·분야 간 연결 맥락·국내 연관성을 소재부터 편집기 계획까지 이관하고 누락 시 차단
- 8개 사이트 빈 수집 작업 생성, 기사·추천 추가, 자동 백업과 최종 확정
- 원문 사실과 운영자 분석, 발표·계획·투자·실증·상용화·실적과 수치 성격 검증
- 네이버 초안 길이, 태그, 출처, 이미지 지시문과 경력 연수 표현 검증
- 최근 공개 유사 네이버 기술 글의 표시 사례를 반영한 기술 글 이미지 3장 기준
- 모든 게시 이미지를 3:2·1200×800px JPEG·450KB 이하로 통일하는 원본 보존형 변환·검증
- 게시글 제목과 별도로 H2는 기본서체·굵게·밝은 블루(`#4A78E0`)·밑줄 없음·19px·위 32px·아래 21px을 사용한다. 링크처럼 보이는 혼선을 막기 위해 밑줄·가짜 링크·장식 이미지·전체 폭 표 선은 사용하지 않는다. H3는 기본서체·검은색·굵게·밑줄 없음·16px·위 24px·아래 12px, 일반 본문은 기본서체·15px·줄높이 27px·양쪽 정렬·마지막 줄 왼쪽 기준
- 게시글 제목 아래 네이버 기본 연회색 구분선은 그대로 유지하고 색상 변경이나 삭제를 하지 않는다.
- H2 바로 다음 H3는 총 12px, 소제목 바로 아래 이미지는 별도 빈 문단 없이 네이버 기본 간격으로 연결하며, 일반 문단 뒤 18px과 도입 뒤 육하원칙 요약·회색·녹색·주황색 1열 전체 배경 상자 기준을 적용
- 표 바로 다음 H2는 빈 문단 없이 연결해 실제 화면 총간격 30px 이하, 참고자료와 관련 글은 하나의 원자 블록·한 셀·항상 보이는 1px 회색 실선(`#CDD2D9`) 안에서 6px 간격으로 적용
- 머리글이 있는 데이터 표는 생성 결과의 누락·오류 `data-label`을 해당 열 제목으로 자동 교정하고 헤더·행·셀 개수와 순서를 재검증합니다. 강조 상자와 참고자료 표는 이 검사에서 제외합니다.
- 관련 글은 동일 네이버 블로그의 현재 글 이전·최근 60일 공개 글만 대상으로 관련성 점수와 반복 링크 감점을 적용해 0~3개 선정하며, 동일한 세 링크 조합의 기계적 반복을 방지하고 후보가 없으면 영역 전체를 생략
- `이 글에서 다루는 내용` 상자 바로 다음 H2도 빈 문단과 중복 위 여백 없이 연결해 실제 화면 총간격 30px 이하로 적용
- 낯선 약어·전문용어는 본문 첫 등장 한 곳에만 쉬운 한글 괄호 설명을 붙이고, 핵심 근거기관은 역할과 이름을 최초 한 번만 짧게 굵게 표시하며 이후 반복 표시는 일반 굵기로 유지
- 편집 패키지 생성과 실제 편집기 실행을 구분한다. 패키지는 `네이버편집실행계약.json`을 만들며 모든 원자 동작이 컴퓨터 사용 새 글 실행에 연결되고 PC·모바일 검증을 통과하기 전에는 완료로 표시하지 않는다.
- 바탕색 강조 상자는 제목 15px·700, 제목 아래 회색·주황 8px/육하원칙 녹색 10px, 본문 줄높이 1.75·문단 뒤 18px, 내부 여백 16px 18px·왼쪽 선 4px·모서리 4px를 적용하고 간격용 빈 문단을 추가하지 않는 기준
- 본문 2,600자 이상에서 국내 영향·향후 확인 내용이 겹치지 않을 때만 네 번째 배경 상자를 허용하는 조건부 기준
- 대표 이미지의 중앙 정사각형 안전영역과 본문 이미지 역할·삽입 위치 계획
- 네이버 공식 기준 우선 적용, HTML·부적합 태그·반복 문단 차단과 검색 노출 비보장 원칙
- 네이버 집계 통계 기반 독자 반응 분석, 최소 표본 판정과 안전한 기본값 유지
- 저장소 밖 작업 폴더의 진행 상태·실패·재시도 기록과 결과 덮어쓰기 방지
- 단계 순서 검증과 마지막 완료 단계·다음 단계 기록
- 기술 기사는 소재 수집부터, 소개·운영자·정책 글은 네이버 초안부터 시작하는 유형별 작업 상태
- 작성 URL 기록은 보존하되 다음 수집 후보에서 자동 제외하지 않고 사용자가 다시 선택할 수 있도록 허용
- 명령어 없이 새 작업 생성, 단계별 JSON 선택·검사·보관과 상태 확인을 하는 Windows 화면
- Windows 화면에서 선택 기사 사실검증 준비와 검증 자료 네이버 초안 준비
- 최근 7일 후보의 제목·매체·날짜·선정 이유·요약을 확인하고 PowerShell에서 번호 1~3개를 입력하는 사용자 선택 흐름
- Windows 화면에서 프롤로그 검증 초안·390px 미리보기·비공개 편집기 계획 일괄 준비
- 컴퓨터 사용 관찰 결과와 편집기 계획을 저장 전·후로 대조해 비공개·본문·태그·카테고리·공지·공개 발행 여부 검증
- 구조화 `editorBlocks`를 `편집기재구성계획.ps1`로 변환해 기존 화면을 임의 보정하지 않고 전체 본문을 재구성한다. 일반 문단 18px, 마지막 독자 질문→참고자료 32px을 도구가 삽입하고 비공개 저장 후 새로고침·PC/모바일 실측으로 지속성을 확인한다.
- `편집기재구성실행검증.ps1`은 각 동작 전 본문 포커스와 동작 후 문단 수·정확 문자열·문단 합침·간격 높이를 검사하며, 오류가 하나라도 있으면 비공개 저장을 허용하지 않는다.
- 관찰 전 안전값을 비워 둔 저장 전·후 편집기 관찰 양식 생성과 미관찰 자료의 검증 통과 차단
- 네이버 첫 인사, 운영자 소개와 이용 안내 초안

작업자료의 필드와 단계별 기준은 `콘텐츠기준\작업자료_형식.md`에서 확인합니다.
네이버 스마트에디터의 안정 요소와 저장 안전순서는 `콘텐츠기준\네이버_편집기_요소.md`에서 확인합니다.
네이버 공식 기준, 구독자 선호, 블로그 고유 원칙의 적용 순서는 `콘텐츠기준\네이버_작성_우선순위.md`에서 확인합니다.
일반 구독자 중심의 유사 블로그 비교와 채택·제외 기준은 `콘텐츠기준\유사블로그_벤치마크.md`에서 확인합니다.
독자 반응으로 글 길이·주제·검색 의도를 보완하는 기준은 `콘텐츠기준\독자반응_분석기준.md`에서 확인합니다.
요구사항별 구현·부분 구현·미구현 상태는 `개발현황.md`에서 추적합니다.
`요구사항_대조표.md`는 `DEVELOPMENT_REQUIREMENTS.md` 1~10절을 현재 증거와 대조하고 완료를 막는 필수 항목을 분리합니다.

## 자동 테스트

Windows PowerShell 5.1에서 다음 파일을 각각 실행합니다.

```powershell
& '.\테스트\개발범위_테스트.ps1'
& '.\테스트\작업자료검증_테스트.ps1'
& '.\테스트\작업상태_테스트.ps1'
& '.\테스트\초안검증기_테스트.ps1'
& '.\테스트\사용자화면_테스트.ps1'
```

전체 검사는 다음 한 줄로 실행할 수 있습니다.

```powershell
& '.\테스트\전체_테스트.ps1'
```

현재 단계는 자료 형식, 검증 로직, 작업상태·백업, Windows 화면과 실제 프롤로그·기술 글 비공개 저장 검증까지 구현되었습니다. 실제 기사 수집 반복 자동화, 실패 지점별 자동 재개와 운영 표본 검증은 이어서 개발합니다.

새 글 실행은 선택 글별로 성공·실패를 분리합니다. 일부 글이 실패해도 완성 글은 `준비된 글`에 즉시 표시되며, `실패한 글만 다시 작성` 버튼은 기사 재검색과 번호 재선택 없이 보존된 실패 후보만 다시 실행합니다. `완성 글 편집기 입력 계속`은 이미 만든 실행 패키지의 편집기 입력만 재개합니다.

## 이미지 자동화

기술 글은 대표 이미지 1장과 본문 설명 이미지 2장, 총 3장을 사용합니다. 세 장 모두 3:2 비율로 생성하고 `프로그램\이미지최적화.ps1`이 1200×800px JPEG로 변환합니다. 네이버 편집기 표시 폭은 340px·가운데 정렬로 통일하되 원본 크기는 유지합니다. 장당 450KB를 넘으면 설정된 최저 품질 범위 안에서 단계적으로 압축하며 원본 파일은 변경하지 않습니다.

`프로그램\이미지작업준비.ps1`은 검증된 초안의 이미지 지시문과 역할·삽입 위치를 글별 작업 계획으로 만듭니다. 현재 이미지 생성 자체는 Codex에서 수행하고 생성 결과를 원본 폴더에 전달합니다. 별도 유료 이미지 API와 자격증명은 연결하지 않습니다. `프로그램\이미지검증.ps1`은 3장, JPEG, 동일 크기와 용량을 게시 전 다시 확인합니다.

## Windows 화면 실행

`프로그램\네이버자동화.ps1`을 Windows PowerShell 5.1로 실행합니다. 현재 화면은 새 작업 생성, 프롤로그 준비, 유사 블로그 선정, 소재 수집·사실검증·네이버 초안 JSON 검사와 결과 보관, 편집기 저장 전·후 결과 검사, 진행 상태 확인, 운영 후 독자 반응 분석을 제공합니다. 검증된 초안에는 비공개 편집기 계획과 390px 로컬 모바일 미리보기를 함께 만듭니다. 공개 게시 기능은 포함하지 않습니다.

한글 스크립트는 Windows PowerShell 5.1이 올바르게 읽도록 UTF-8 BOM 형식을 사용하며, 전체 테스트에서 파일 인코딩도 함께 검사합니다. 화면 자체의 버튼 배치와 크기는 사용자 Windows 바탕화면에서 추가 확인이 필요합니다.

`설치준비.ps1`은 명시적으로 `-Install`과 `.lnk` 대상 경로를 제공할 때만 바로가기를 만듭니다. 기존 바로가기는 덮어쓰지 않으며, 자동 테스트에서는 임시 폴더에 만든 바로가기의 실행 대상과 인수를 확인한 뒤 정리합니다.

`백업내보내기.ps1`은 개발 소스 폴더 밖의 지정 위치에 새 복구용 ZIP을 만듭니다. 기존 ZIP을 덮어쓰지 않으며, 상태·로그·임시파일이나 토큰·쿠키·세션·비밀번호·자격증명 이름의 파일이 소스에 있으면 백업을 중단합니다.

## 반복 수집 작업

`프로그램\수집작업.ps1`은 설정된 8개 사이트의 빈 수집 파일을 만들고, 확인한 기사와 추천을 단계적으로 추가하며, 변경 전 파일을 자동 백업합니다. 완료 URL과 사이트별 최대 2개 제한을 추가 시점에 검사하고 `Finalize` 단계에서 전체 수집 규칙을 다시 확인합니다.

`프로그램\사실검증준비.ps1`은 확정된 수집 결과에서 사용자가 선택한 기사 URL을 찾아 매체명·제목·URL·게시일과 AI 융합 분야·핵심 분석축·연결 맥락·국내 연관성을 새 사실검증 작업으로 옮깁니다. 사실과 분석 필드는 빈 상태로 만들며, 근거를 채우기 전에는 사실검증기를 통과할 수 없습니다.

`프로그램\초안준비.ps1`은 검증을 통과한 사실검증 자료만 네이버 초안 작업으로 전환합니다. 원문 출처와 사실·분석·불확실성 및 편집 맥락을 이관하지만 제목·본문·태그·이미지 지시문은 비워 둡니다. AI 연결·분야 간 영향·국내 의미·사실과 판단 구분·억지 연결 배제 확인값도 작성 전에는 거짓이므로 초안 검사를 통과할 수 없습니다.

운영 데이터가 쌓인 뒤 `프로그램\독자반응분석.ps1`로 만든 결과를 초안 준비 화면에서 선택하면 권장 길이·관심 카테고리·검색 의도·모바일 신호가 `readerGuidance`로 함께 전달됩니다. 네이버 공식 기준과 사실 정확성이 우선이며, 표본 부족 결과는 기본 목표 2,000~3,000자를 유지합니다.

`프로그램\벤치마크선정.ps1`은 글 주제마다 공개 네이버 블로그 후보를 검증합니다. 오래된 대형 블로그와 일반 독자 적합성이 낮은 후보를 먼저 제외하고, 통과 후보 중 공개 이웃 수가 가장 큰 블로그를 주 참고 대상으로 선정합니다. 결과는 초안의 `benchmarkReview`에 사용하며 기존 파일을 덮어쓰지 않습니다.
