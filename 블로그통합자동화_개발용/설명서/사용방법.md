# 블로그 통합 자동화 사용방법

## 실행

바탕화면의 흰색 `블로그통합자동화` 바로가기를 더블클릭합니다. 바탕화면 바로가기가 없다면 `바탕화면_바로가기_만들기.ps1`을 한 번 실행합니다. PowerShell에서 스크립트 실행이 제한되면 이 프로젝트 폴더에서 다음 명령을 한 번 실행할 수 있습니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\블로그통합자동화\바탕화면_바로가기_만들기.ps1
```

버튼 화면에서 `새 글 작성 시작`을 누릅니다. 공개 RSS·Atom·사이트맵·최신 기사 페이지에서 URL 후보를 수집한 뒤 Codex가 원문을 검증합니다. 후보는 8개 사이트에서 사이트별 최대 2개, 전체 최대 16개이며, 검은 명령 화면에서 `1` 또는 `2,4,7`처럼 번호를 선택합니다. Codex CLI에 기존 로그인이 되어 있어야 하며 별도의 API 키는 사용하지 않습니다. 실패 글만 다시 작성하려면 `최근 실패 작업 재시도`, 설치 상태는 `실행 환경 점검`, 이미지 수량은 `이미지 준비 상태 확인` 버튼을 누릅니다.

소재 번호 입력란 앞에 사이트명 등 다른 문자가 붙더라도 프로그램은 끝부분의 번호를 분리해 사용합니다. 번호 형식이나 존재 여부가 잘못되면 처음 명령 화면으로 돌아가지 않고 같은 후보 목록에서 다시 입력받습니다. 세미콜론은 쉼표로 보정되며, 선택을 중단하려면 번호 입력란에 `취소`를 입력합니다. `명령:` 화면에서는 번호가 아니라 먼저 `시작`을 입력해야 합니다.

같은 날짜에 다시 `시작`하면 `기록/후보목록_YYYY-MM-DD.json`의 후보를 재사용합니다. 새로 수집하려면 프로젝트 폴더에서 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\블로그통합자동화\프로그램\후보목록_새로검색.ps1`을 실행합니다. 이 명령은 공개 자료 후보만 갱신하며 Codex 글 생성은 실행하지 않습니다. 수집 결과는 `기록/후보수집_로그.txt`, 실제 글을 작성한 URL은 `기록/작성한_URL.txt`에 UTF-8로 기록됩니다. 공개 자료 수집이 실패하면 기존 Codex 웹 검색으로 전환합니다.

## 결과와 이미지

성공한 글은 `작업완료/YYYY-MM-DD/번호_소재명`에 저장됩니다. 최종 게시용 주 파일은 `Blogger에_붙여넣을_본문.html`입니다. 이 파일은 전체 본문을 화면 폭 100%·최대 800px로 가운데 배치하고, 이미지 위치를 화면 폭 100%·최대 400px·높이 자동·가운데 정렬로 만듭니다. 내부 생성 원고인 `본문.html`은 복구와 비교를 위해 숨김 보관합니다. Blogger 글쓰기 화면을 **HTML 보기**로 바꾼 뒤 게시용 파일의 내용만 붙여넣고, Blogger 편집 화면 전체나 `메타데이터.txt`를 함께 복사하지 마십시오.

글 폴더에는 사용자가 다루는 `압축이미지`, `원본이미지`, `Gemini_이미지_01~04`, `메타데이터`, `Blogger에_붙여넣을_본문`만 보이게 합니다. 내부 `본문`, 통합 이미지 프롬프트, 작업정보, 미리보기와 완료 표시는 기능 유지와 복구를 위해 삭제하지 않고 Windows 숨김 파일로 보관합니다.

로컬 WebP 4장은 Blogger에 업로드하기 전까지 `blogger.googleusercontent.com` 실제 주소를 가질 수 없습니다. 최종 게시 단계에서 `압축이미지/01.webp`부터 `04.webp`까지를 순서대로 Blogger의 네 이미지 위치에 업로드합니다. 업로드 후 Blogger가 만든 실제 이미지 주소가 네 곳에 들어갔는지 확인하고, 각 이미지의 `alt`와 `title`, 최대 400px·가운데 정렬·모바일 자동 축소 스타일을 유지한 상태에서 먼저 임시저장합니다. API 연동 전에는 이 업로드 단계만 수동으로 수행하며 공개 게시 전 최종 승인을 거칩니다.

질문 상자 바로 아래에는 하나의 `출처` 영역이 만들어집니다. 선택한 실제 기사 URL을 반드시 포함하여 매체명·기관명만 보이는 클릭 링크를 1~3개 한 줄에 표시하고 쉼표와 공백으로 구분합니다. 상세 URL은 이름의 링크에 연결하고 URL 전체 주소와 긴 기사 제목은 화면에 표시하지 않습니다. 별도의 `자료 및 참고` 영역은 만들지 않습니다. 본문 링크는 핵심 수치·중요 발표일·정부 정책·기업 공식 발표·오류 정정·원문 확인이 꼭 필요한 주장에만 쓰며, 같은 URL을 하단 출처에도 표시합니다.

주황색 질문 상자의 질문은 기사 원문, 보완 자료, 본문 전체와 마지막 판단을 모두 검토한 뒤 독자가 가장 궁금해할 핵심 미해결 사항 한 가지로 작성합니다. 본문에서 이미 답한 사실이나 어느 기사에도 붙일 수 있는 일반 질문은 사용하지 않으며, 기사에 맞는 다음 선택·대안·전환 시점·장기 위험을 45~90자의 한 문장으로 묻습니다.

Gemini 이미지 생성에는 `Gemini_이미지_01.txt`부터 `Gemini_이미지_04.txt`까지를 **한 번에 한 파일씩** 사용합니다. 각 파일을 별도의 새 이미지 요청으로 입력하고 결과 한 장을 저장한 뒤 다음 번호로 진행합니다. 네 파일이나 `이미지_프롬프트.txt` 전체를 한 번에 입력하면 Gemini가 2×2 콜라주 한 장으로 합칠 수 있으므로 사용하지 않습니다. `이미지_생성용_전체프롬프트.txt`에는 이 순서를 안내하는 내용만 저장됩니다. 이미지 자체는 사용자가 생성하거나 준비해야 합니다.

각 글의 `원본이미지` 폴더에 JPG, PNG 또는 WebP 이미지 **정확히 4장**을 넣습니다. 실행 창과 함께 시작되는 감시 프로그램이 5초 간격으로 확인하여 `압축이미지/01.webp`부터 `04.webp`까지 만듭니다. 파일명 가나다·숫자 순서로 01~04가 정해집니다. 긴 변은 최대 1600픽셀, WebP 품질은 86으로 설정했습니다. 원본 파일은 보존하고 `백업`에도 사본을 만들며, 네 장을 실제 위치에 연결한 `미리보기.html`을 자동 생성합니다. Blogger 업로드와 게시 자체는 사용자가 확인 후 수동으로 진행합니다.

이미지가 4장이 아니거나 변환에 실패하면 완료 표시를 만들지 않고 `기록/오류기록.txt`에 원인을 남깁니다. 기존 결과 파일은 덮어쓰지 않습니다. 글 작업상태와 원본 응답은 `작업대기`에 남기며, 성공한 브라우저 변환 임시파일은 즉시 삭제합니다.

## 제한

이 개발 단계의 프로그램은 이미지 **생성**, 블로그 **게시**, Blogger **업로드**, Search Console·AdSense 연동, 휴대전화 승인을 하지 않습니다. 기존 게시글도 수정하지 않습니다. 기사 검색과 새 글 작성은 현재 로그인된 Codex CLI와 그 실행 환경의 웹 검색 기능에 의존합니다. 자동 생성 글의 기사 사실관계와 문장은 게시 전에 직접 확인하세요.
