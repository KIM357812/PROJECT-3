# 블로그 통합 자동화 직원용 간단 사용설명서

## 1. 사용 범위

- 이 도구는 앞으로 새로 작성할 한국어 Google Blogger 글을 준비하는 용도입니다.
- 기존 게시글을 수정하거나 자동으로 공개 게시하지 않습니다.
- 실제 Blogger 입력·이미지 업로드·예약 또는 공개 게시에는 담당자의 최종 확인이 필요합니다.

## 2. 실행 전 준비

- Windows 11 컴퓨터를 사용합니다.
- Chrome 또는 Edge가 설치되어 있어야 합니다.
- Codex CLI에 본인에게 허용된 계정으로 로그인되어 있어야 합니다.
- 다른 사람의 비밀번호, 로그인 세션, API 키를 복사하거나 공유하지 않습니다.

## 3. 프로그램 실행

1. 바탕화면의 흰색 `블로그통합자동화` 아이콘을 더블클릭합니다.
2. `블로그 글 작성 도우미` 창에서 먼저 `실행 환경 점검`을 누릅니다.
3. Codex CLI, 모델, 프롬프트, 필수 폴더와 이미지 변환 브라우저가 모두 `[정상]`인지 확인합니다.
4. 점검용 검은 창의 결과를 확인한 뒤 창을 닫습니다.

## 4. 새 글 작성

1. `새 글 작성 시작`을 누릅니다.
2. 검은 창에 최대 16개의 최신 소재가 표시될 때까지 기다립니다.
3. 작성할 소재 번호를 `1` 또는 `2,4,7`처럼 입력하고 Enter를 누릅니다.
4. 글 작성 중에는 검은 창을 닫거나 같은 버튼을 다시 누르지 않습니다.
5. 완료된 글 폴더가 열리면 다음 파일이 있는지 확인합니다.
   - `Blogger에_붙여넣을_본문.html`
   - `메타데이터.txt`
   - `Gemini_이미지_01.txt`부터 `Gemini_이미지_04.txt`
   - `원본이미지`, `압축이미지` 폴더

## 5. 글 작성 실패 시

- 내부 사실검증 항목이 3개 미만이면 프로그램이 사실검증표만 한 번 자동 보완하고 다시 검사합니다.
- 자동 보완 뒤에도 실패하면 검은 창을 닫고 `최근 실패 작업 재시도`를 한 번 누릅니다.
- 재시도할 때 소재 번호를 다시 입력하거나 `새 글 작성 시작`을 다시 누르지 않습니다.
- 같은 오류가 반복되면 계속 재시도하지 말고 오류 화면을 캡처하여 담당자에게 전달합니다.

## 6. Gemini 이미지 준비

1. `Gemini_이미지_01.txt`의 내용을 Gemini의 새 이미지 요청에 입력합니다.
2. 이미지 한 장을 저장한 뒤 02, 03, 04 파일도 각각 별도의 새 요청으로 진행합니다.
3. 네 프롬프트를 한꺼번에 입력하지 않습니다. 한꺼번에 입력하면 2×2 콜라주 한 장이 만들어질 수 있습니다.
4. 생성한 이미지 정확히 4장을 해당 글의 `원본이미지` 폴더에 넣습니다.
5. `블로그 글 작성 도우미`에서 `이미지 확인·자동 변환`을 누릅니다.
6. `압축이미지` 폴더에 설명형 파일명의 WebP 이미지 4장이 생겼는지 확인합니다.

## 7. Blogger에 입력하기

1. `완성 글 폴더 열기`를 눌러 해당 글 폴더를 엽니다.
2. `Blogger에_붙여넣을_본문.html`을 열어 제목, 본문, 수치, 날짜, 질문과 출처를 검토합니다.
3. Blogger 글쓰기 화면을 `HTML 보기`로 전환합니다.
4. `Blogger에_붙여넣을_본문.html`의 내용만 붙여넣습니다.
5. `압축이미지`의 01~04 이미지를 본문의 네 이미지 위치에 번호 순서대로 올립니다.
6. PC와 휴대전화 미리보기에서 이미지, 표, 바탕색 박스와 본문 줄바꿈을 확인합니다.
7. 제목은 `메타데이터.txt`의 `최종 권장 제목`을 우선 사용합니다.
8. 담당자의 승인을 받은 뒤에만 예약 또는 공개 게시합니다.

## 8. 게시 전 최종 확인

- 제목과 본문의 핵심 내용이 일치하는가
- 날짜, 수치, 회사명과 기술명이 정확한가
- 이미지가 정확히 4장이고 내용과 맞는가
- 이미지가 가운데 정렬되고 글과 충분히 떨어져 있는가
- 모바일에서 본문과 표가 화면 밖으로 넘어가지 않는가
- 질문 아래 출처가 1~3개이고 클릭되는가
- 기존 글 링크가 있다면 현재 블로그의 실제 관련 글인가
- 오탈자, 중복 문장과 과장 표현이 없는가

## 9. 버튼의 용도

- `새 글 작성 시작`: 최신 소재 검색과 새 글 작성
- `최근 실패 작업 재시도`: 실패한 글만 다시 작성
- `이미지 확인·자동 변환`: 원본 이미지 4장 확인과 WebP 변환
- `실행 환경 점검`: 프로그램 실행 조건 확인
- `완성 글 폴더 열기`: 작성된 글 결과 확인
- `전체 기능 검증`: 관리자 또는 개발 담당자가 프로그램 전체를 시험할 때 사용

## 10. 주의사항

- `작업대기`, `기록`, `백업`, `임시파일`의 내용을 임의로 삭제하지 않습니다.
- 기존 결과 파일을 이름이 같은 새 파일로 덮어쓰지 않습니다.
- 숨김 `사실검증표.md`는 내부 확인자료이므로 Blogger에 붙여넣지 않습니다.
- `메타데이터.txt` 전체를 본문에 붙여넣지 않습니다.
- 비밀번호, API 키, OAuth 토큰과 브라우저 로그인 정보를 글 폴더나 GitHub에 저장하지 않습니다.
- 문제 발생 시 먼저 화면을 캡처하고 어떤 버튼을 눌렀는지 담당자에게 알립니다.
